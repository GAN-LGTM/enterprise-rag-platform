# 运维手册（私有化交付版）

## 1. 日常巡检

| 项目 | 命令 / 位置 | 正常判据 |
| --- | --- | --- |
| 服务状态 | `docker compose --env-file .env.production -f deploy/docker-compose.prod.yml ps` | 全部 `Up (healthy)` |
| 健康检查 | `curl -f https://<域名>/api/health` | 返回 200，各组件 `ok` |
| 就绪探针 | `curl -f https://<域名>/api/ping` | 200（K8s/Docker 健康检查使用） |
| 指标 | `curl http://<api>:8000/metrics`（内网） | Prometheus 文本格式 |
| 错误日志 | `docker compose --env-file .env.production -f deploy/docker-compose.prod.yml logs --since 1h api \| grep error` | 无持续增长 |

## 2. 日志

- 应用日志：`/data/logs`（容器内）→ 卷 `raglogs`，结构化 JSON（structlog），含 `trace_id`
- 访问日志：Nginx 容器标准输出
- 日志滚动：Compose 已配置 `json-file` 单文件 20MB × 5
- 按 trace 追踪：从前端响应头或日志取 `trace_id`，全局检索即可还原一次问答全链路

## 3. 关键指标

指标名均以 `rag_` 开头（定义见 `backend/app/metrics.py`，端点 `/metrics` —— 注意**没有** `/api` 前缀）。
**告警规则已随交付物提供**，见 `deploy/monitoring/alerts.yml`（12 条），本表只列排障时最常用的几项。

| 指标 | 含义 | 建议告警 |
| --- | --- | --- |
| `rag_llm_calls_total{model,status}` | LLM 调用（ok/timeout/empty/error/unavailable） | 失败率 > 20% 持续 5min；出现 unavailable 立即告警 |
| `rag_llm_tokens_total{model}` | 生成 token 量 | 突增 3 倍排查 |
| `rag_request_latency_seconds{endpoint}` | 请求耗时 | P95 > 8s |
| `rag_node_latency_seconds{node}` | 工作流各节点耗时 | 单节点 P95 > 5s（区分是检索慢还是生成慢） |
| `rag_cache_total{result}` | 缓存 hit / miss | 命中率 < 5% 持续 15min（Redis 可能已降级） |
| `rag_permission_denied_total{reason}` | 权限拦截 | 突增视为越权探测，核对审计日志 |
| `rag_stream_active` | 活跃 SSE 流 | > 200 视为连接堆积 |

## 4. 备份与恢复

> **重要**：数据库是主存储（向量库、会话、审计、反馈都在里面）。
> 备份失败会以**非 0 退出码**明确报错，绝不"跳过继续"——
> 天天报成功却没备份过数据库，比没有备份更危险。

```bash
# 每日备份（crontab：0 2 * * *）
python backend/scripts/backup.py backup

# 查看备份历史（含是否完整）
python backend/scripts/backup.py list

# 校验最近一份备份真的可恢复（只读，不落库）
python backend/scripts/backup.py verify

# 恢复：会自动先对当前库做一次安全备份，返回的 revert_to 可用于反悔
python backend/scripts/backup.py restore backup-20260929-020000

# 按 BACKUP_KEEP（默认 14 份）清理旧备份
python backend/scripts/backup.py prune
```

旧参数 `--out / --keep-days / --list` 仍兼容（历史运维手册不会失效），但推荐上面的子命令写法。

备份目录（`BACKUP_DIR`，生产挂在独立卷 `backupdata`）建议同步到异地（对象存储 / NAS），
并**每季度演练一次恢复**——能备份不等于能恢复，只有真的恢复过一次才算数。

## 5. 容量与扩容

| 资源 | 扩容方式 |
| --- | --- |
| API 吞吐 | 调大 `WEB_CONCURRENCY`（建议 = CPU 核数），或多副本 + 负载均衡 |
| 向量检索 | PostgreSQL 增加内存与 `maintenance_work_mem`；HNSW 索引参数见 `sql/002_index.sql` |
| 缓存 | Redis `maxmemory` 与 LRU 策略；命中率低时延长 TTL |
| 模型推理 | vLLM 增加 GPU / 张量并行，或接入多副本推理集群 |

## 6. 变更管理

1. 任何配置变更走 `.env.production` + 重启，禁止容器内热改；
2. 数据库 DDL 变更先在预发执行，窗口内灰度；
3. 版本升级先备份、留回滚镜像标签。

## 7. 应急处理

| 故障 | 处置 |
| --- | --- |
| LLM 不可用 | 自动降级到备选模型（3s 首字超时 → `LLM_FALLBACK_MODEL`），连续失败熔断 30s 后重试 |
| Redis 不可用 | 自动降级本地 LRU 缓存（`CACHE_AUTO_FALLBACK=true`） |
| PostgreSQL 不可用 | 读多写少场景可临时开 `DB_AUTO_FALLBACK`，但**生产不建议长期运行内存库** |
| 单容器异常 | `docker compose --env-file .env.production -f deploy/docker-compose.prod.yml restart api`；仍异常则用备份回滚数据卷 |
| 疑似越权 | 立即在审计日志按用户/时间检索，必要时吊销账号并导出留痕 |
| 答非所问 | 用 `trace_id` 在 `data/intent_log.jsonl` 反查当次判定（层/意图/置信度），见 §8 |

## 8. 意图准确性运营（上线后持续做）

意图不是"配一次就完事"，靠线上数据反哺。每月一次（或点踩率升高时）执行：

```bash
cd backend
python scripts/intent_report.py                     # 复盘报告
python scripts/intent_report.py --export-finetune samples.jsonl
```

看四个数：

1. **规则层覆盖率**（目标 ≥80%）—— 低说明 L1 词典不够，报告【5】会给出高频且未覆盖的候选词，
   业务确认后加进 `app/intent/rules.py`，覆盖率会逐月上升、成本逐月下降；
2. **低置信样本** —— 落在 L3/L4 且置信度 <0.8 的问句，是补词与微调的第一优先；
3. **点踩样本** —— 与判定记录按问题文本关联后的疑似判错集，**必须人工标注**；
4. **导出集** —— 标注 `label` 后训练 BERT-tiny，替换 `BERT_MODEL_PATH` 并打开 `BERT_ENABLED`，
   L3 从"关键词打分"升级为真实语义分类。

判定留痕默认写在 `backend/data/intent_log.jsonl`（20MB 自动滚动保留一份 `.1`），
可用 `APP_DATA_DIR` 改路径；备份脚本已覆盖该目录。

## 9. 联网工具（天气 / 行情 / 百科 / 节假日 / 搜索）运维

五个外部工具都在 `app/tools/` 下，按 `realtime.TOOL_ROUTER` 注册表调度，**任何失败都静默降级**，不影响主流程。

| 工具 | 数据源 | 是否需密钥 | 备注 |
| --- | --- | --- | --- |
| `weather` | Open-Meteo | 否 | 免密钥，只需放行出站 HTTPS |
| `market` | 东方财富 → 腾讯财经兜底；汇率 open.er-api | 否 | 主源被限流会自动切备源 |
| `encyclopedia` | 百度百科 OpenAPI | 否 | 查无此条即弃权，交回内网 RAG |
| `holiday` | timor.tech | 否 | 按国务院办公厅年度放假安排 |
| `websearch` | Tavily / Serper（配了就用）→ 必应 → 搜狗 | 可选 | 见 9.2 |

它们属于"公网"路径，与内网 RAG 严格分路，受同一总开关 `PUBLIC_SEARCH_ENABLED` 控制；
行情与参考类（百科+节假日）另有 `REALTIME_MARKET_ENABLED` / `REFERENCE_TOOLS_ENABLED` 独立开关（总开关关闭时随之关闭）。

### 9.1 合规总开关（金融 / 政务零外网场景必看）

| 配置 | 行为 |
| --- | --- |
| `OFFLINE_MODE=true`（私有化默认）且未设 `PUBLIC_SEARCH_ENABLED` | 天气/行情/百科/节假日/搜索**全部默认关闭**，满足"零外网流量"承诺 |
| `PUBLIC_SEARCH_ENABLED=true` | 开启联网问答（上述五类工具将产生外网请求） |
| `PUBLIC_SEARCH_ENABLED=false` | 强制关闭，即使 `OFFLINE_MODE=false` 也不出网 |
| `PUBLIC_SEARCH_ENABLED=true` + `REALTIME_MARKET_ENABLED=false` | 只关掉 A 股行情类问答，其余保留 |
| `PUBLIC_SEARCH_ENABLED=true` + `REFERENCE_TOOLS_ENABLED=false` | 只关掉百科与节假日，其余保留 |

### 9.2 结构化搜索 API（可选，但强烈推荐）

不配密钥时，`websearch` 走内置的必应/搜狗**网页抓取**（已过滤导航站与词典页，但质量天然不如接口）。
配上之后切换为直接向搜索 API 要结构化 JSON，不再抓网页正文：

```env
SEARCH_API_PROVIDER=tavily      # tavily | serper
SEARCH_API_KEY=tvly-xxxxxxxx
```

- `tavily` 面向 LLM 设计，额外返回一段可直接进 Prompt 的检索摘要，效果最好。
- 留空或密钥无效时**自动回退**到网页抓取，功能不受影响（日志会记 `tool.search.api_fail`）。

- 生产 `preflight` 自检会在 `OFFLINE_MODE=true` 却开启公网搜索时**告警**（`public_search` 项），提示与零外网承诺冲突。
- 关闭后，天气/行情/搜索分支被跳过，闲聊里的时效问题退化为"礼貌说明无法获取实时数据"，业务问答不受影响。
- **一键关掉公网搜索**：把 `PUBLIC_SEARCH_ENABLED` 设为 `false`（或删掉该行，保持 `OFFLINE_MODE=true`）即可，无需改代码。

### 9.3 出网数据脱敏（防内网泄露）

公网搜索引擎只收到"问题本身"，绝不携带内网上下文：

- 出网前过 `tools/websearch.sanitize_query`，剔除**部门全名 / 用户显示名 / 账号 / 所属部门 / `INTERNAL_TERMS` 内部术语**。
- `INTERNAL_TERMS`（逗号分隔）可写入 `.env`，用于剔除公司内部产品代号、项目名、黑话。
- 脱敏日志：`tool.search.redacted`（列出被剔除词），便于审计"这次出网到底过滤了什么"。
- 脱敏后若句子为空，宁可发原句也不发空查询（空查询反而暴露"这里有不能说的东西"）。

### 9.4 来源标注与体验区分

外部工具回答一律前端橙色徽章，模型被要求末尾注明"以上信息来自公开互联网，仅供参考，不代表公司内部信息"：

| 来源 | 徽章 |
| --- | --- |
| 公网搜索 | 🌐 公网搜索结果 · 仅供参考，不代表公司内部信息 |
| 天气 | 🌐 实时天气（公网）· 仅供参考 |
| 行情 | 📈 实时行情数据（公网）· 仅供参考，不构成投资建议 |
| 百科 | 📖 公开百科词条 · 仅供参考，不代表公司内部规定 |
| 节假日 | 📅 法定节假日安排（公网）· 以国务院公布为准 |

内网知识库回答：绿色徽章「📚 来自公司知识库」+ 引用卡片（文档名/页码/部门），用户可溯源。

### 9.5 排障

| 现象 | 排查 |
| --- | --- |
| 天气答不出 / 答"无法获取实时数据" | 看日志 `tool.weather.fail`（常见：内网无外网、`geocode_miss` 城市名未识别）；Open-Meteo 免密钥，只需放行出站 HTTPS |
| 问"什么是 X"没走百科 | 看日志 `tool.ency.miss`（查无此条，属正常弃权）或 `tool.ency.fail`；命中判断在 `reference.is_encyclopedia_query`，内部词会被护栏拦下（属预期） |
| 问"X 月 X 号放假吗"没走节假日 | 看日志 `tool.holiday.no_data` / `tool.holiday.fail`；注意"我们公司什么时候放假"会被内部护栏拦下并交回内网 RAG，这是**预期行为** |
| 演唱会/电影类问题仍答"未在知识库中检索到" | 看日志 `tool.search.ok` / `tool.search.no_result`；确认意图是否命中 `chitchat`（规则 `生活娱乐/时效话题`），以及是否命中强时效触发；并确认 `PUBLIC_SEARCH_ENABLED` 是否为开 |
| 搜索结果质量差（导航站/词典页） | 首选方案：配 `SEARCH_API_PROVIDER`+`SEARCH_API_KEY` 走结构化接口（见 9.2）。不配则靠 `websearch._is_junk_result` 域名黑名单过滤，可在该函数补充黑名单 |
| 内网私有化部署 / 关闭公网 | 无外网或开关关闭时五类工具全部跳过/超时降级（超时 6~8s），业务问答不受影响 |

注意：搜索结果只作为当次 Prompt 上下文，**不写回向量库**，也不会写进内网 RAG 缓存，不会污染企业知识；
答案要求注明来源网站，便于用户自行核验。
